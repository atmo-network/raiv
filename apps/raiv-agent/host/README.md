# Native registry, step bridge and live run routing

Package `raiv-agent-host`, library `raiv_agent_host`, requires Rust 1.86 for pinned Wasmi 2.0.0. `GuestVm::new` validates an import-free module, installs finite memory/table/instance and per-step fuel limits, and checks the required typed exports. No WASI or host functions are linked. Native-only Core/minicbor dependencies supply typed data validation without entering the guest or Core std feature graphs.

## Native terminal presentation/input port

The application presents only a sealed NativeFailure observation: the closed ClientError enum/static messages, numeric HTTP status and preserved StreamError/NormalizeError subtypes, or allowlisted native-stage labels. SSE declares length or refusal/filter through distinct failed labels; framing, missing terminal/DONE/EOF and normalization failures stay distinct without accepting any partial reply. Live transport/preparation and mapping/mode/routing/continuation refusals retain this RAM-only diagnostic across generic driver error wrapping. Unknown stage strings normalize to guest_refusal; arbitrary Box<dyn Error> chains are never formatted in UI. No raw provider bodies/headers/text/arguments/reasoning, checkpoint diagnostic field, provider error-body reads, retry, acceptance override or extra inference is added. A historical withheld error cannot be reconstructed from admission/checkpoint bytes; unresolved state still blocks submission.

Linux terminal::{TerminalUi,UiLimits,Role,Signal,TerminalSession} supplies exactly two regions: role-labelled ephemeral history and focused prompt. Unicode grapheme caret/deletion, display-cell vertical movement, multiline input (Ctrl+J/Shift+Enter), Home/End/Ctrl+A/E, Ctrl+U clear, PageUp/Down history, bracketed paste and Esc/Ctrl+C exit are supported. Enter emits a locked presentation-only Submit signal only on a visible nonempty prompt/press; paste/repeat/release/disabled/too-small/pending states cannot automatically submit. Caller must separately authorize native Actor events/grants/pins and use the existing live driver. complete_input affects presentation only and never implies accepted boundary or recovery permission.

UiLimits are independent presentation caps, not Core context policy: prompt/paste/over-cap history entries reject atomically, and bounded history may evict only old RAM presentation entries. Nothing persists or enters guest context. ESC/C0/DEL and directional override/isolate controls are sanitized; role tags repeat on wrapped/logical lines, preserving source identity in narrow/scrolled views. Session requires owned TTY stdin/stdout, excludes a second process-local owner, restores raw mode/alternate screen/bracketed paste/cursor on partial-open error/normal drop/unwind, and exposes no inference/FS/approval capability. Native Crossterm ingress has already allocated a completed Event before reducer caps; full raw-paste ingress/RAM limits, signals/abort/system failures and physical terminal diversity are not proven.

TestBackend narrow/intermediate/wide/resize/scroll buffers and separate owned-PTY termios drop/unwind witnesses prove this port. The native interactive command now binds independently approved initial pins/finite grants, current-prompt ActorWake admission and exported known-accepted continuation through the actual driver. Model/status history is ephemeral, unresolved/AwaitAction states block and effects remain separate. Complete model text is presentation DATA; a known accepted boundary can survive failed next-pin export as accepted + blocked. Native synchronous transport defers exit until the bounded decision and discards queued input rather than auto-approving another event. Operational raw-ingress/async-interrupt/physical-terminal evidence and real-provider smoke remain open.

## Host inference normalization

`inference::normalize_chat_completion(body, request_id, model, &Limits)` converts one complete Chat Completions JSON response to closed normalizer-v1 CBOR, without itself performing HTTP, environment lookup, guest decisions or acceptance. The caller supplies its native pending ID/exact selected model; response IDs never select correlation. Raw response and every nested argument JSON string have full syntax/UTF-8/depth/byte/aggregate-entry/duplicate-key preflight before owned-map conversion (escaped-equivalent duplicates reject, Unicode normalization is not performed). Raw/normalized bytes use max_model_reply_bytes; raw JSON additionally has a64-level parser ceiling. Malformed/refused/filtered/truncated/model-mismatched completions fail with static diagnostics, not raw provider error echo.

Canonical DRISL arguments preserve literal keys, nulls/falsy values, arrays and full-u64 without float coercion. Scalar/array/non-model-integer argument rejection and multi-call selection remain Core-owned; multiple complete calls preserve every ID without selecting a first. Provider token reports retain unknown/zero/full-u64; Core model/local counters are0 in report DATA, never substituted for admitted guest counts or real cost. Optional reasoning_content stays only in the native NormalizedReply continuation, not its guest bytes/state. Normalization alone supplies retention, not a request-mode contract; the explicit ReasoningSession below owns bounded same-Run continuation. This port alone is not a stream assembler, live profile, online CLI or W08–W10 completion; partial SSE must not call it until the assembly contract below has proved completeness.

`inference::sse::ChatCompletionStream` incrementally accepts raw bytes with separately selected whole-wire/per-event/event-count bounds. UTF-8/CRLF splits, LF/CR endings, initial BOM, comments and SSE metadata are framed before duplicate-safe per-event JSON parsing. Tool names/argument fragments and native reasoning are joined only in RAM; bounded provisional_text is presentation DATA, never successful inference. Model/choice/response-ID/index/type/refusal/finish/usage conflicts poison the stream. Missing terminal or DONE, unterminated trailing data, truncated tool JSON, extra post-DONE DATA, late error or overflow cannot finish successfully, and a failed stream cannot be reused.

Only consuming finish after **successful HTTP EOF** returns normalizer-v1 data; HTTP status/content type/timeouts and proving EOF belong to the transport owner below, not to this DATA parser. Terminal chunk or DONE alone is not permission to advance a guest. Identical terminal usage may be acknowledged but is never summed; unknown/zero/full-u64 reports retain their meanings. The full generated JSON body and final normalized frame have independent combined bounds; no guessed JSON closure, fabricated completion or partial successful checkpoint. Complete multi-call IDs remain Core selection-owned. Non-streamed legacy function_call is likewise explicitly unsupported rather than silently discarded. Existing scripted guest equality tests use complete mock SSE only, not the selected live model or authenticated provider.

## Guest-owned live profile/request mapping

The guest constructs closed exact endpoint/model/thinking metadata, with only Continue/Yield tools and no registered no_op/Finish tool. A complete validated reply without calls selects intrinsic guest/Core Finish (text may be empty); invalid/refused/truncated/contradictory replies and budget failure never do. Transport schemas remain verbatim, with no special strict-empty-function sampling or fabricated call. With no enabled tools, omit tools/tool_choice/parallel_tool_calls rather than sending an invalid empty API list. Changed metadata/module requires new explicit approval, never rebinding saved sources. inference::request::encode_chat_request checks the selected Definition/profile against guest model parameters and native provider configuration, maps only the guest-budget-enabled descriptors in their original order, and losslessly converts all seven model-compatible CBOR context sections into JSON. The first policy/mandate section is transported as system content; every remaining section, including declared tools, machine DATA, history, Memory and RAM trajectory, is transported together as user DATA. The host neither adds behavioral instructions nor truncates/reconstructs the guest's context. In addition to that unchanged complete DATA view, current guest RAM turns are now encoded as Chat Completions assistant.tool_calls/tool messages with exact native call IDs, names, serialized arguments and full guest result records. All rejected multicalls/results remain present; null arguments are not converted into {}, IDs are not remapped and failed results never become successful. A valid no-call reply ends the Activation, so it is not replayed as a corrective turn or orphan tool result. Closed trajectory fields/result joins are checked before serialization. This is a redundant transport-role view of current validated RAM DATA, not a persistent/recovered provider transcript, host decision engine or hydration of old Episode calls. Combined JSON byte cap covers both views; overflow refuses rather than dropping context. Output/request/JSON bounds remain independent; incompatible model/endpoint/parameters/policy or insufficient request cap fails rather than rebinding.

The default compiled profile emits thinking:type disabled, one choice, automatic single-tool preference and max_tokens/stream policy. It is not generic support for every OpenCode catalogue API or reasoning continuation: check_chat_reply_mode must reject unexpected nonempty native reasoning instead of silently forgetting provider-required fields. Model/policy/mandate changes require a different approved Definition; existing agents are not rewritten. Mock native/actual-WASM profile progression and JSON/SSE equality prove the codec/retained Activation boundary, not authenticated HTTP or full operational TUI readiness. Native application acceptance now has offline actual-WASM provider-port witnesses; real-provider/TUI evidence remains in BACKLOG.

The separate opencode_reasoning_definition pins exact deepseek-v4.1-flash with explicit low/high effort; disabled inference metadata remains unchanged, but tool/policy removal changes Definition identity. inference::request::ReasoningSession::{new,encode,record} emits enabled thinking/reasoning_effort and requires a present native reasoning_content string for replies with tool calls (empty is preserved, missing is rejected). A complete validated zero-call final may omit reasoning because it creates no assistant continuation to replay; no empty thought is fabricated. Disabled mode still rejects nonempty thought. Use only the originating authorized Run::pending pair; record only after the exact complete tool reply is successfully routed into a Pending VM. A terminal no-call reply cannot be recorded; attempting to record one poisons the carrier rather than enabling continuation. It keeps normalized reply bytes plus reasoning privately in RAM, checks Definition/ticket origin/consecutive IDs and exact guest-trajectory text/call-ID/name/argument joins, then adds reasoning only to corresponding current assistant messages. Multicall/corrective tool turns remain intact; final zero-call replies are never replayed. Each retained frame+thought is bounded by max_model_reply_bytes, aggregate storage by max_context_bytes and captured max_model_calls_per_activation (actual admission remains Run/guest-owned); total encoded request cap also includes all replayed reasoning. Repeated/stale/foreign tickets, wrong mode, mismatched joins, allocation/byte caps poison the carrier; discard the run, never retry/fake a boundary. No Debug/Clone/serialization/export, transcript restoration, guest/Memory/checkpoint/UI reasoning, native decisions or authority are added. Drop the carrier at boundary/failure; a new Run requires a new empty carrier and cannot replay the old origin. The native application binds this port through optional inference.reasoning_effort = "low"|"high"; absence selects the current default disabled profile. One carrier is created per execute_request (shared by file wake/resume and native interactive submission), and only Pending replies are recorded after successful VM routing. It drops final thought and retained carrier before sealing/acceptance; errors discard RAM and retain conservative durable Launched/old root. New source/effort/module requires independent approval, not rebinding. Config/init/status remain credential/network-free. Native JSON/SSE plus actual-WASM application/CLI/Controller tests cover fresh wake, installed-ledger resume, private state/UI and per-record/aggregate/request overflow; the prior Go/high owned-PTY witness passed two accepted semantic Memory tasks on its original approved profile/module. Current natural completion has a separate fresh bounded Go/high witness after the terminal-mode guard fix, not retrospective coverage from the older run. That successful run included final reasoning; omitted final thought remains a separate offline-proven class. That is bounded live acceptance/continuity evidence, not general model behavior, low-effort live support or global authority.
