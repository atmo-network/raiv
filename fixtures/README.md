# Format fixtures

This directory owns pinned input vectors, their provenance and the Raiv-specific acceptance overlay. The six structural codecs, embedded records, genesis and bounded checkpoint-data restoration have independent conformance evidence. A coherent data graph is not an accepted host lineage or runnable Activation.

The vectors are frozen golden data. Their expected bytes, hashes and CIDs were produced independently of Raiv's codec when each vector was created (see the per-file provenance below). [`lib/src/fixture_tests.rs`](../lib/src/fixture_tests.rs) checks that every vector stays canonical and self-consistent under the independent Ciborium oracle: bytes equal the record, hashes and CIDs match, one CID names one block, and closure byte totals add up. New vectors are assembled with the same oracle and reviewed before they are pinned.

## Selected wire/model profile

- [`dasl-testing/`](dasl-testing/): Unmodified MIT-licensed fixtures at revision `b6ea320b07b385c417aaae265425ec334a3fd70c`; 105 rows across eleven families. Upstream profiles can disagree for the same bytes; preserve license/attribution.
- [`raiv-format.json`](raiv-format.json): Twenty supplemental witnesses for DRISL links, encoded-key ordering, truncation, minimal widths and trailing data. The positive link digest independently binds the empty CBOR map (`a0`).
- [`raiv-profile.json`](raiv-profile.json): Explicit decisions for all 125 rows, selected by file/index and checked against names. No upstream tag or `type` implicitly defines Raiv behavior.

Profile boundaries:

- `structural_wire` is preflight, not typed state validity. Bare scalars may pass wire checks but cannot replace structural blocks.
- `model_value` excludes Bytes/Links/floats and restricts integers to ±(2^53−1); runtime u64 fields still accept their full range. Positive runtime byte strings do not authorize model bytes.
- All float encodings reject, including finite float64, subnormals, negative zero, NaN and infinities. Numeric reduction is not another encoding path.
- Generic DASL raw/SHA-256 identifiers cannot replace structural DRISL links. The upstream Big DASL/BLAKE3 positive is deliberately rejected; it does not widen Raiv's profile.
- Map keys follow encoded-key order, not plain Rust lexical order. Duplicate/noncanonical keys reject before insertion can erase evidence. UTF-8 is validated without Unicode normalization; both decomposed-Unicode upstream rows accept.
- Nonminimal widths, indefinite forms, unsupported tags/simple values, malformed links and concatenated objects reject.

[`format/demo_scenario.json`](format/demo_scenario.json) is independent preferred-CBOR/hashlib/base32 five-boundary DATA for the fixed native unit-world recipe and template agent/world IDs. The host scenario recipe reproduces it, and the fixture test keeps it self-consistent.

## Standalone records and identities

All 38 complete standalone vectors match the independent Ciborium oracle. `$bytes`/`$link` in fixture documents mark runtime Bytes/Links only; ordinary model maps with those names remain ordinary notes, not wire conventions or discovered dependencies.

- [`format/memory.json`](format/memory.json): Empty/populated first-standard sparse `intents`/`strategy`/`tactics` records, including an empty object in an array position; independently assembled preferred CBOR with Python hashlib/base64 hashes/CIDs. Empty enabled Memory is `{}`; persisted nulls/empty object fields reject.
- [`format/limits.json`](format/limits.json): Complete demo/full-u64 policy subrecords; normative scalar assembly and Python hashlib byte digests. Limits is not another block kind or authority.
- [`format/definition.json`](format/definition.json): Synthetic veto/survivor Definitions with complete descriptors/profiles/Limits. Initial draft bytes came from the independent serde DAG-CBOR encoder. Current first-standard memory/profile/tool schema/policy and max_patch_entries vectors were independently rebuilt with preferred CBOR/Python hashlib/base64; tests verify them with Ciborium, not that removed dependency. Organic descriptor/policy metadata explicitly separates the closed intended vocabulary from tolerant root selection. The fixture test keeps this metadata and its dependent links and closure totals self-consistent. Reference Definitions contain only Continue/Yield tools, with no no_op descriptor; lifecycle terminal steps use tool_id=null to represent a complete zero-call reply. Tool/policy changes legitimately alter synthetic Definition/dependent CIDs without changing wire versions or hash domains; it has no accepted-checkpoint/recovery input or migration path.
- [`format/command.json`](format/command.json): Complete embedded Commands, full-u64 tool versions and plain record hashes from independent canonical assembly.
- [`format/identity.json`](format/identity.json): Exact Episode/Action/Command domain preimages/digests, including zero/u64::MAX action indexes. Historical independent codec preimages and Python hashlib pin the expected hashes; a plain Command hash is not its domain-bound digest.
- [`format/terminal.json`](format/terminal.json): Positions/Receipts with null/raw references, full-u64 positions and all three terminal outcomes; normative scalar assembly and Python hashlib byte/command-domain hashes. Not provenance/finality proof.
- [`format/accounting.json`](format/accounting.json): Three BudgetAdmission/four Usage subrecords with distinct/zero/full-u64 counters and unknown/known-zero/mixed costs; independent scalar assembly before encoder stabilization and Python hashlib. Not grant authorization or a lifetime ledger.
- [`format/input.json`](format/input.json): Five ActivationInputs spanning two null-Receipt wakes, full-u64 metadata and three terminal-result labels; independent schema-based preferred-CBOR assembly and Python hashlib/base64. Not prepared/admitted input.
- [`format/boundary.json`](format/boundary.json): Four Boundaries spanning both exits, null/non-null Memory and full-u64 metadata, linked to existing Input/Memory vectors; independent assembly and Python hashlib/base64. Link validity alone does not prove target kind/closure.
- [`format/episode.json`](format/episode.json): Four empty/nonempty open/closed Episodes with nullable entry Memory and ordered Boundaries; independent assembly and Python hashlib/base64. Synthetic IDs and standalone links are not a coherent accepted lifecycle.
- [`format/state.json`](format/state.json): Five roots spanning both memory profiles, genesis shape, both continuations and full-u64 revision; independent assembly and Python hashlib/base64. Linked standalone records/synthetic IDs are not verified genesis or accepted lineage.

## Closure bundles and staged meaning

- [`format/genesis.json`](format/genesis.json): Complete two/three-block closures for both profiles. Existing pinned Definition/empty-Memory/revision-zero bytes, independently rechecked hashes/CIDs, exact required closure and aggregate encoded-byte totals establish genesis data restoration—not host registration/availability.
- [`format/closure.json`](format/closure.json): Three candidate closures from pinned standalone vectors: no-memory AwaitAction, memory/history AwaitActor and full-u64 AwaitAction. Inspection establishes exact unique totals and one materialized read per CID; synthetic IDs/linkage intentionally do not establish full restoration.
- [`format/roles.json`](format/roles.json): Three independently assembled preferred-CBOR/hashlib/base32 bundles; all nineteen blocks match Ciborium. Role checks cover completed-none, pending-none and memory-profile history/current. Two remain intentionally partial: pending-none uses an unlisted tool; completed-and-pending-memory mismatches descriptor authority. Tool-binding tests reject them without rewriting their pinned bytes.
- [`format/identity_graphs.json`](format/identity_graphs.json): Descriptor-bound two-action pending/completed bundles with exact Episode/Action preimages and Python hashlib/base32 witnesses. Ciborium verifies all sixteen block bytes and both action indexes, which differ from Boundary ordinals. These support restored protocol-data positives, not accepted HEAD/dispatch.

Ciborium-mutated graph regressions cover roles, IDs, ordinal/cause/terminal Receipt pairing, profile/retained-memory joins, history/revision windows, Usage, grants and declared Yield descriptors. They preserve nullable costs, legitimate Memory reuse and raw caller history capacity (including zero), and never invent evicted-prefix/genesis anchors, grant freshness/top-ups/units or code/argument authorization. Six `RestoredAgent` positive snapshots span genesis and post-genesis memory/none data; the memory-profile case corrects the old role fixture's authority in a separate test-built graph rather than rewriting its negative vector. Missing/corrupt-block, typed-view/buffer-pointer, caller-cap and no-hydration/fallback regressions exercise composition.

- [`format/lifecycle.json`](format/lifecycle.json): Six independently generated checkpoint witness sets for object-patch → trade failure → retry success → set_wake → Finish → two ActorWakes. They pin exact Input/Memory/Boundary/Episode/root bytes/CIDs and required-closure sets/totals, plus transient patch-result values/canonical bytes/SHA-256. Mixed unsupported roots, an all-skipped patch and a processed no-effect patch demonstrate feedback without forced correction, alias mapping or implicit Finish; report hashes are DATA, not new structural blocks. They were generated with a narrow preferred-CBOR encoder and Python hashlib/base32 that imported no Raiv code; no migration or legacy corpus is involved. These are checkpoint DATA witnesses, not host acceptance or actual effects.

## Independent oracle and focused checks

[`lib/src/format/oracle.rs`](../lib/src/format/oracle.rs) uses test-only Ciborium 0.2.2, defaults disabled, with Ciborium's own canonical comparator rather than Raiv/minicbor ordering helpers. It supplies fixture conversion, borrowed map mutation and raw/link witnesses while preserving duplicate-key/full-u64 evidence. All fourteen model/record/identity families use it; Ciborium is neither a runtime dependency nor a public generic Value API. No IPLD/CID crates remain in normal/build/dev graphs. Unrelated conformance/Command/identity/Receipt/input/accounting vectors remain unchanged. Current synthetic memory/Definition/Limits vectors and their dependent links/roots/totals were regenerated for the first standard, not migrated accepted data; Memory versions remain 1 and Command bytes/identity hash domains are unchanged. No legacy corpus or read-time compatibility layer is introduced.
