# Changelog

## 0.0.2: provider profiles, readable Memory and pinned sessions

Compatible with 0.0.1 data: no state format, structural record, hash domain or golden fixture changed.

- Core forbids `unsafe` code at the crate root; crate documentation now explains Raiv and opens with a compiled sparse-Memory/patch example, and rustdoc builds without warnings.
- The root README is a short entrypoint (purpose, three-layer architecture, demo, library use, status). The detailed Core API guide moved verbatim to the library README with crates.io-safe links, and the stale claim that host I/O, inference, acceptance and terminal were future work is corrected.
- Core renders model values as compact JSON: `ModelValue::json()` and `Memory::json()` (`no_std`, iterative, RFC 8259 escaping, canonical key order), verified by round-trip through an independent JSON parser. Wire formats and fixtures are unchanged.
- Reference TUI: role gutter (You / Agent / Memory), colors, word wrapping and a compact narrow-terminal mode. Startup shows the restored checkpoint and accepted Memory; each boundary adds one checkpoint line and any Memory change instead of a ten-line status dump; stop messages say what to do next. A scrolled-back reader now keeps their position while output arrives, as the specification requires.
- Launcher: sessions keep their own pinned guest and grant plan, so rebuilding Raiv (including any Core change or toolchain update, which changes guest bytes) no longer orphans existing agents. New sessions default to 20 prompts/launch, 4096 tokens and 60s/request, with a mandate that asks the agent to save lasting facts in Memory. Headless `status` adds a `memory=` JSON line. Verified live: an existing session restored and extended its Memory through the new TUI.
- Specification revision 0.0.2 matches and extends the implementation: closed inference provider families `opencode-go` and `openai-compatible` (§18.3), compact JSON presentation of model values (§8.4), actionable patch feedback and the `anyOf` plane-schema form (§6.2), activation failure categories at the guest ABI (§16.2), Memory presentation in the TUI and the actual headless command set (§18.5), pinned local sessions (§18.6), the real configuration schema (§18.4) and a current workspace layout (§3). Five acceptance IDs were added (C19, W12–W14, M17; 96 in total). No state format, structural record, hash domain or golden fixture changed.
- A new session can use the generic OpenAI-compatible profile: `RAIV_PROVIDER=openai-compatible ./run.sh` runs `qwen3.8-flash` on the OpenCode endpoint with `OPENCODE_API_KEY`, and `RAIV_BASE_URL`, `RAIV_MODEL` and `RAIV_API_KEY_ENV` select another compatible endpoint. The project names only `deepseek-v4.1-flash` and `qwen3.8-flash`. The new profile sends no provider extensions, uses an `anyOf` plane schema, never replays provider reasoning, and accepts dated model snapshots (`<model>-YYYY-MM-DD`) and empty-id streaming continuations, both found in live testing. Existing `opencode-go` Definitions and all fixtures are byte-identical. Verified live with `qwen3.8-flash`: Memory saved on the first try across all three planes, then updated and pruned in a reopened session; native/Wasmi equality covers the new profile.
- Core: rejected patches return actionable `invalid_patch: …` feedback naming the rule and expected shape (`PatchError::feedback`). Seeded mutation fuzzing runs about 35,000 mutated golden vectors through every public decoder and the patch path in the ordinary suite, checking for no panics, exact canonical bytes on acceptance, valid JSON rendering and unchanged Memory on failure.
- Guest failures carry the specification's categories (`corrective_turns_exhausted`, `budget_exhausted`, `context_limit`) instead of a single `activation_failed`, and the TUI names them.
- The TUI shows Memory as readable `plane.key = value` entries and, at each boundary, only the added, changed and removed entries.
- CI adds rustdoc with warnings denied, a documentation link and anchor checker (`.github/scripts/check-links.sh`) and the launcher regressions with actual-Wasmi startup. The pre-release evidence log moved behind a pointer to the `v0.0.1` changelog (289 KB → 5 KB), the backlog was rewritten as a prioritized list, and the stale checksum gate was removed from the README in line with the recorded owner decision.
- Compression: removed the redundant `apps/README.md` index; the old live PTY witness (`test-live-interactive.py` and its three Rust live tests), superseded by the launcher witness `test-live-launcher.py` (offline actual-WASM recall witnesses stay); two orphan one-off live diagnostics together with the 248-line provider error-body classifier only they reached; the 60 KB narrative host README, now a 3 KB module map; and the root README's duplicate architecture sections. All remain available at the `v0.0.1` tag.
- No Python: the three fixture generators are replaced by `fixture_tests`, which checks all 167 frozen vectors and 21 closures under the independent Ciborium oracle (bytes equal records, hashes and CIDs match, one block per CID, closure totals), and CI drops its Python step. The live launcher witness is `test-live-launcher.sh`, checking the exact `memory=` JSON from `status`; the link checker is `check-links.sh`. Both were checked offline, and the witness's PTY path was exercised against a rejected credential; its live success path spends inference and was not run.
- Gardening: the guest README describes the current profiles and failure categories, the root README's status is a short works/not-yet list, glued-number typos ("a1024-token", "MSRV1.85", …) are fixed, and `AGENTS.md` records the tooling-language rule.
- Formatting: all Rust code separates items with a blank line (1,729 lines inserted across 168 files; nothing else changed, verified by a blank-insensitive diff).
- `raiv-agent` no longer panics when its reader closes early (for example `status | head`).
- The Rust boundary workflow passed on GitHub for the published 0.0.1 commit `5dcf7de`, the commit crates.io built raiv 0.0.1 from and the target of the `v0.0.1` tag used by library README links.

## 0.0.1: MVP — portable agent continuity and a runnable WASM reference

- Portable `raiv` library (`no_std + alloc`, Rust 1.85): bounded fixed-profile CID/DRISL records, borrowed checkpoint restoration/context projection, registered RAM Activation, resource accounting and validated immutable commit candidates. Core performs no external I/O or trusted host acceptance.
- Organic Memory: exact sparse `intents`/`strategy`/`tactics` patches, atomic selected-content validation, merge/delete/array semantics and complete processed/skipped/change feedback. No synonym remapping, transcript journal or silent checkpoint migration.
- Natural completion: complete correlated zero-tool-call replies seal intrinsic Finish, including silent finals. Local calls Continue and external calls Yield; malformed, refused, incomplete, truncated and exhausted inference never becomes completion.
- Isolated import-free Rust WASM guest and native Wasmi 2 bridge: bounded versioned CBOR ABI, retained activation, private request correlation, explicit native admission/candidate acceptance and no production native-guest fallback.
- Linux local durability and conservative recovery: held no-follow directories, exact-byte publication/CAS, Reserved→Attempted→Launched accounting and separately pinned adoption. Uncertain outcomes never authorize automatic relaunch/refund or effect replay.
- Reference application: Bash `./run.sh`, two-region TUI and Go/deepseek-v4.1-flash/high inference with a 1024-token bounded envelope. Real-provider textual acceptance, Memory patch and fresh-process semantic recall are verified; native reasoning remains private same-Run RAM. Old failed namespaces are preserved; the new default is `var/raiv/chat`.
- Scripted retry-and-sleep scenario and an independent synthetic unit world: durable pending/terminal records and exact installed-Receipt continuation demonstrate local lifecycle composition without real trading, funding or scheduler authority.
- Release packaging: public `raiv 0.0.1` crate; host/guest packages remain repository applications. Independent fixtures/upstream attribution, Core/guest MSRV 1.85 and host MSRV 1.86 are preserved. Host checked atomic IDs use a stable/MSRV-compatible implementation after the GitHub stable CI lint caught a standard-library deprecation; exhaustion still fails without wrapping. The owner removed the redundant documentation checksum-manifest gate; source-response provenance remains documented. Specification table separator cleanup changes Markdown only, not requirements, wire bytes or hash domains.

### Support boundaries

This is a bounded working MVP, not production or financial/blockchain readiness. Real pricing/funding, external Actor/Receipt authentication, global/current acceptance, CAR/IPFS/provider-loss availability, full fuzz/resource/acceptance coverage and physical-terminal/async-interruption evidence remain open in BACKLOG. The UI uses synchronous bounded inference; exit is deferred during a call. Local fsync/SIGKILL tests are not physical power-loss or global finality proof.
